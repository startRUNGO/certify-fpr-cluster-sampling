## 1. 发生了什么

配对运行（`runs/lacuna_hc_paired_20261026T080905Z`）在 lh_paired_rev1 开头的站点检查处退出，退出码 3。检查输出原样如下：

> PAIRED SITE CHECK: 483 fields, 51342 negatives paired one-to-one; max |delta score| 0.00309, median 0 (limit 1e-4)

- 视野列表和阴性身份都一一配对成功。
- 阴性分数大多数逐位相同，中位数为 0；但个别阴性的差值最大达到 3.1e−3，超过了勘误 1 定的 1e−4。
- B 组没有做任何计算，没有任何结果。

## 2. 原因判断

- 中位数为 0、最大值约 1e−3，符合 GPU 推理在不同批组成下的数值差异。lh 全量推理中阳性数不同，同一个阴性所在批次的组成随之不同，批边界上的卷积算法或归约顺序可能改变。
- 配错样本不会是这个样子。分数的量级是 ±10，配错的话差值会远大于 1e−3。
- 勘误 1 定的 1e−4，是按"约 1e−6 量级"的经验估计的，定得太紧。这属于技术原因，不是结果驱动：B 组没有任何结果，A 组的结果也没有被读取。

## 3. 更正

1. 站点检查中阴性分数的上限，从 1e−4 放宽到 **1e−2**，约为观察到的最大值的 3 倍，仍比分数的典型间距小两个数量级。
2. 站点检查另外打印 |Δ| > 0、> 1e−4、> 1e−3 的阴性**个数**。只报个数，不报分数。
3. **起约束作用的判据不变**：paired_check 对 lh 中 c0 量的断言照勘误 1，覆盖率 |Δ| ≤ 0.002，FPR 均值 |Δ| ≤ 1e−4，n_labeled_neg 完全相等。这组断言直接检验"只依赖阴性的量是否相同"，分数上的微小差异如果没有翻转任何结论，就会通过；如果翻转了，就停下。
4. B 组按通用规则技术性重跑一次，输出到新目录。A 组已经完成，不重跑，单独执行 check_A。
