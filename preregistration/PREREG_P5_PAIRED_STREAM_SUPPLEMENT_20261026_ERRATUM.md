## 1. 校验范围：只包括 c0 的量（原文写多了）

- **错误：**原文把 B1u_c1s、B1u_c2s 和 s10、s11 中 c1s 相关的量，也列为"只依赖阴性"。
- **事实：**原脚本里视野级的居中统计 cstat() 用的是该视野**全部细胞**的分数（包括阳性），全局中位数 gm 也是用全部细胞算的。所以 c1s、c2s 居中之后的阴性分数依赖阳性，去重或重建都会使它们发生真实的变化。
- **更正：**断言差值为 0 的量只包括不居中（c0）的那些：
  - rev1 和 rev7 中的 R1_2、R1_field、R1_all、B1、B1u_c0；
  - s10 中的 `c0|B1`、`c0|B1u`、`c0|R1_2`；
  - s11 中的 `R1_2c0`、`U_c0`；
  - s7 的解析部分（只依赖每个视野的阴性个数）。

  c1s、c2s 的量改为**真实效应**，与 S3 一样，报点估计和配对区间。
- **连带更正：**主会话此前在两份判读里写的"B1、B1u、R1 只依赖阴性"，应当改为"B1、B1u_c0、R1"。判读里实际引用的证据（B1、B1u_c0）不受影响。

## 2. s5：没有可以配对的原随机流

## 3. lh 的阴性分数：浮点容差（事先写定）

- **问题：**lh 的 logits 是全量重新推理得到的。批次的组成与旧版不同，因为里面有新的阳性，GPU 在不同批组成下可能产生约 1e−6 量级的浮点差。lh 的 c0 ICC 与旧版相差 1.4e−9，说明确实存在这种差。所以"逐个严格相等"不可行。
- **更正：**
  1. 阴性按裁剪身份配对（field_id 加裁剪框 x0, y0, x1, y1），新旧逐个对应。不能一一对应就停下。
  2. 匹配上的阴性分数（logit 差），最大 |Δ| 必须 ≤ 1e−4，否则停下。要报告最大值和中位数。
  3. lh 中 c0 量的断言改为：覆盖率 |Δ| ≤ 0.002，即 1,000 次抽样中最多 2 次翻转；实现 FPR 均值 |Δ| ≤ 1e−4；n_labeled_neg 的差值恰好为 0。还要报告 per-draw 认证结果翻转的次数。
  4. lb_dedup 复用旧版的 logits 文件本身，所以仍按原文 ≤ 1e−9。
